# AI label scanning prototype

The Android app captures one still image into app-private storage, decodes barcode and QR evidence again from that exact image, and sends the image plus typed code evidence to the private Qwen3.5 vision model running on the Spectrum GPU through Ollama. The selected `qwen3.5:9b-q8_0` model and tailnet endpoint are build configuration, not credentials. No OpenAI key is embedded in the app or required at build time.

Every populated field reaches the review form with its source. A checksum-valid deterministic GTIN wins over an inconsistent AI reading. Multiple local GTINs block automatic GTIN selection. Marketplace identifiers and arbitrary QR payloads remain evidence and never become GTIN or SKU values. Fields absent from the label say so explicitly. A missing mass can be suggested only when a strong local SpoolmanDB-Community match has one unanimous weight; the suggestion remains marked for package-size confirmation.

The endpoint is bound only to the workstation's Tailscale address and forwarded through the persistent private SSH tunnel to Ollama on `spectrum-gpu`; it is not exposed on the LAN or public internet. The Android device must be connected to the same tailnet. Tailscale provides authenticated encrypted transport, while the app uses the endpoint's tailnet IPv4 address because the workstation's existing HTTPS Serve route belongs to another service. A public or multi-user release still requires a dedicated authenticated gateway, TLS termination, quotas, abuse controls, retention policy enforcement, and published privacy behavior.

`qwen3.5:9b-q8_0` was selected over the 27B Q4 model after a five-label comparison and the exact Android workflow. The 9B model preserved the expected material and color on all five fixtures, made one brand OCR error (`FLASHFORCE` for `FLASHFORGE`), and completed the full ANYCUBIC Android extraction in 64 seconds. The 27B model read all five benchmark brands correctly but took multiple minutes for the full Android schema, so it remains installed as an accuracy fallback rather than the default.

## ChatGPT plan provider

The app can also analyze labels through the owner's ChatGPT plan, using OpenAI's Sign in with ChatGPT flow for personal, locally run projects. When a ChatGPT account is connected it is the first provider; the private Ollama route above is the fallback when ChatGPT fails or the plan limit is reached, and the review list says which provider answered. With no account connected, behavior is unchanged.

Sign-in is OAuth 2.0 authorization code with PKCE and OpenID Connect against `https://auth.openai.com`, using dynamic client registration (`dynamic_agent_client`) and a loopback redirect to `http://127.0.0.1:{port}/auth/callback` served by the app itself for the duration of the attempt. The listener binds to loopback only, checks the `Host` header, path, and `state`, and ignores anything else. While an attempt is pending the app holds a time-limited `shortService` foreground service. Without it the device freezes the app seconds after the browser comes to the front (observed on the Razr as `moto_freezer`), and the redirect to the loopback listener is never answered. If the service cannot run, returning to the app unfreezes it and the queued redirect completes. The completion page links to `spoolforge://chatgpt-signin`, which only brings the app back to the front and carries no data. The ID token's RS256 signature, issuer, audience, expiry, and nonce are verified against the issuer's published keys before a connection is stored.

Requests go to `POST https://api.openai.com/v1/responses` with the OAuth access token, `store: false`, `stream: true`, the label photo as an `input_image` data URL, and the same label JSON schema used for the local model. If structured output is rejected, the request is retried once with the schema described in the prompt. The model is fixed at `gpt-5.6-terra` and is not user-selectable. It was chosen by running all five models the plan offered against the six reviewed label fixtures on the device: it tied for the most exact fields (72 of 77), reconstructed every product term, made the fewest unsupported claims, and had a median time of 14.4 seconds against 21.6 to 43.7 seconds for the others. The numbers and method are in `work/ai-label/CHATGPT_PLAN_BENCHMARK.md`; `DeviceChatGptModelBenchmark` repeats the comparison when the plan's model list changes.

There is no API key and no client secret. Access and refresh tokens are encrypted with an AES-GCM key held in the Android Keystore and stored in app-private preferences; app backup is disabled. Refresh tokens rotate and the new one is written before use. Disconnect revokes the refresh token and deletes local tokens while keeping the issued registration, so signing in again does not register the app twice. Server error text is never shown or logged, because validation errors can echo the request.

Limits: this uses OpenAI's preview of ChatGPT plan usage, which needs an eligible ChatGPT plan and is permitted for open-source and personal locally run projects. OpenAI documents the flow for desktop apps; the Android loopback flow follows the same protocol but is not an officially documented target. A distributed or commercial build would need OpenAI's approval. The implementation is written against the public protocol documentation and contains no code from OpenAI's noncommercially licensed devkit.
